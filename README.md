# Сертконтроль

> **README этапа 1.** Разделы следуют чек-листу «Формат сдачи» кейса; финальная версия — этап 3.
> **Все данные реестра в текущей версии — ТЕСТОВЫЕ (демо-снапшот), а не официальный источник.**

## Назначение

Бот и мини-приложение в MAX для импортёров и селлеров: проверить сертификат или декларацию о соответствии
по номеру или PDF-выписке, поставить документ на контроль и получить уведомление, когда его статус в реестре изменится.

## Основной пользовательский сценарий

1. Переслать боту выписку (PDF) или номер документа.
2. Получить карточку вердикта: статус, сроки, заявитель, продукция, дата данных; каждая строка помечена «факт / расчёт / рекомендация».
3. Нажать «На контроль».
4. Нажать «Симулировать обновление» (демо-режим).
5. Получить уведомление о смене статуса.

Статус реализации — [`docs/plan.md`](docs/plan.md). Этап 1: шаги 1–3 работают в боте и мини-приложении на демо-данных;
шаги 4–5 (демо-обновление и уведомление) — этап 2.

## Состав и архитектура

| Компонент | Что делает |
|---|---|
| `certd` (C++20, Drogon) | Webhook бота, REST API мини-приложения, распознавание, вердикт, раздача мини-приложения |
| `ingest` (C++20) | Раз в сутки собирает неизменяемый снапшот реестра, считает diff |
| PostgreSQL 16 | Пользователи, портфель, очереди и outbox |
| `web/` (React + TS) | Мини-приложение MAX |
| Caddy (профиль `prod`) | TLS для webhook и мини-приложения на VPS |

Подробно — [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md), решения — [`docs/adr/`](docs/adr/README.md), карта кода — [`CLAUDE.md`](CLAUDE.md).

## Запуск одной командой

```bash
docker compose up --build
```

Проверка: `curl http://localhost:8080/healthz` → `{"status":"ok","db":"ok","snapshot_version":1}`; мини-приложение — http://localhost:8080/.
Файл `.env` для локального запуска не обязателен: без токена бота мини-приложение в браузере работает от тестового
пользователя `1000001` ([ADR-0013](docs/adr/0013-dev-auth-without-max.md)).

## Параметры и переменные окружения

Шаблон — [`.env.example`](.env.example) (все значения пустые; рабочие токены в репозиторий не кладутся).

|---|---|---|
| `MAX_BOT_TOKEN` | — | Токен бота MAX; пусто — бот выключен |
| `MAX_WEBHOOK_SECRET` | — | Секрет webhook `X-Max-Bot-Api-Secret`, 5–256 символов `A-Za-z0-9_-`; обязателен с токеном |
| `MAX_BOT_USERNAME` | — | Публичное имя бота — для кнопок, открывающих мини-приложение |
| `MAX_API_BASE_URL` | `https://platform-api2.max.ru` | Bot API MAX |
| `CERTD_DEV_USER_ID` | `1000001` | Пользователь мини-приложения в браузере без MAX; игнорируется при заданном токене |
| `CERTD_RECOG_THREADS`, `CERTD_RECOG_QUEUE` | `2`, `8` | Пул распознавания PDF и его очередь |
| `POSTGRES_DB`, `POSTGRES_USER` | `sertkontrol` | База и пользователь |
| `POSTGRES_PASSWORD` | пусто | Пусто — локальный режим без пароля во внутренней сети compose ([ADR-0009](docs/adr/0009-local-run-without-secrets.md)); на VPS обязателен |

| `CERTD_PUBLISH_PORT` | `8080` | Порт certd на хосте |
| `CERTD_THREADS`, `CERTD_DB_CONNECTIONS` | `0`, `4` | Потоки IO и соединения с БД |
| `SK_DOMAIN` | — | Домен для TLS (профиль `prod`) |
| `APT_MIRROR` | `http://mirror.yandex.ru/ubuntu` | Зеркало apt при сборке образа ([ADR-0011](docs/adr/0011-apt-mirror-build-arg.md)) |

## Зависимости

- C++: только пакеты Ubuntu 24.04 — [`docker/apt-build-deps.txt`](docker/apt-build-deps.txt), [`docker/apt-runtime-deps.txt`](docker/apt-runtime-deps.txt).
- Web: [`web/package-lock.json`](web/package-lock.json), Node.js 24 ([ADR-0007](docs/adr/0007-node-24-lts.md)).
- Образы: `ubuntu:24.04`, `node:24-slim`, `postgres:16`, `caddy:2`.

## Внешние сервисы и интеграции

- **MAX Bot API** (`https://platform-api2.max.ru`) — бот: webhook, отправка сообщений, ответы на кнопки, скачивание вложений.
  Сертификат API выпущен УЦ Минцифры; его корень встроен в образ ([ADR-0012](docs/adr/0012-mintsifry-root-ca.md)).
  Webhook MAX принимает только HTTPS на 443 — нужен VPS с доменом и профиль `prod` (Caddy).
- **MAX Bridge** (`https://st.max.ru/js/max-web-app.js`) и **MAX UI** (`@maxhub/max-ui`, MIT) — мини-приложение.
- REST API мини-приложения описан в [`openapi.yaml`](openapi.yaml).
- **Реестры Росаккредитации (открытые данные ФСА)** — не подключены: свежесть и формат наборов не подтверждены. Используются тестовые данные (см. ниже).

## Работа с данными

- Реестр хранится в неизменяемом бинарном снапшоте, `certd` отображает его в память ([ADR-0001](docs/adr/0001-registry-in-mmap-snapshot.md)).
- В PostgreSQL — только пользовательские данные: портфель, ИНН поставщиков, очереди. Файлы пользователей не сохраняются.
- Схема — [`db/migrations/`](db/README.md), применяется сервисом `migrate` при старте.

## Тестовые данные

**Все данные реестра — вымышленные демо-записи** (`data/demo/`, этап 1): наименования «ТЕСТОВЫЙ …», ИНН с верной контрольной цифрой, но не реальные.
Мини-приложение постоянно показывает пометку «Тестовые данные».

## Пошаговый сценарий проверки и ожидаемое поведение

**Локально, без MAX:**
1. `docker compose up --build` → `migrate` и `ingest` завершаются с кодом 0 (`ingest` пишет «снапшот v1 готов … ТЕСТОВЫЕ ДАННЫЕ»).
2. `curl http://localhost:8080/healthz` → `200`, `"snapshot_version":1`.
3. Открыть http://localhost:8080/ → вкладка «Добавить» → ввести `ЕАЭС N RU Д-CR.РА08.В.89369/26` → «Проверить».
   Ожидается карточка «✅ Декларация RU Д-CR.PA08.B.89369/26 — действует» с блоками «Факт / Расчёт / Рекомендация»,
   «Данные реестра на 25.09.2026» и пометкой «Тестовые данные».
4. «На контроль» → вкладка «Портфель» → документ в списке; фильтр «прекращён» → пусто; «Снять» → список пуст.
5. Номер `ЕАЭС N RU Д-CR.РА07.В.89369/26` → «Нет в данных реестра» и похожие номера серии 89369/26.
   Другие номера с ожидаемыми вердиктами — [`data/demo/README.md`](data/demo/README.md).
6. Через API: `curl "http://localhost:8080/api/v1/check?number=RU%20D-CR.PA08.B.89369/26"`.

**В MAX (нужны токен, секрет и HTTPS-домен):**
1. Открыть бота → «Согласен».
2. Отправить номер или переслать PDF-выписку → «⏳ Проверяю документ…» → карточка вердикта.
3. «На контроль» → «🔔 … на контроле» с кнопкой «Снять с контроля».
4. Отправить 4 и более номеров → сводка и «Поставить все на контроль».

## Известные ограничения

- Данные ФСА не подключены — работа на демо-данных (свежесть и формат открытых наборов не подтверждены).
- Демо-обновление и уведомления о смене статуса — этап 2; нечёткий поиск и вопрос «Это номер …?» — этап 3;
  фото, OCR и сканер QR камерой — этап 4. Фото сейчас получают ответ «пришлите PDF».
- Скачивание вложений MAX по `payload.url`: нужна ли авторизация и сколько живёт ссылка, в документации MAX не сказано —
  реализовано без токена, проверяется вручную в MAX.
- Без `MAX_BOT_TOKEN` сервер — однопользовательский локальный стенд; не публикуйте порт 8080 в интернет без токена.
- Исходящие сообщения MAX — at-least-once: ключа идемпотентности в документации MAX API не найдено (АРХ §7.5).

## Ручная проверка в MAX (чек-лист)

- [ ] Webhook: `POST /subscriptions` с `url=https://<домен>/max/webhook`, `secret=<MAX_WEBHOOK_SECRET>`; событие доходит, ответ 200.
- [ ] Скачивание PDF-вложения по `payload.url` без токена работает.
- [ ] Кнопки `callback`, `link`, `open_app` (с `MAX_BOT_USERNAME`) отображаются и срабатывают в мобильном и веб-клиенте.
- [ ] Мини-приложение открывается из бота, `X-Max-Init-Data` проходит проверку подписи.
- [ ] HTML-разметка карточки (`<b>`) отображается.

## Остановка и повторный запуск

```bash
docker compose down        # остановить, данные сохраняются в томах
docker compose up -d       # запустить снова
docker compose down -v     # остановить и удалить данные (полный сброс)
```
