# data/demo — демо-источники реестра (владелец R1)

**Статус:** этап 2 — `base.tsv` (снапшот N) и `next.tsv` (снапшот N+1) для сценария «Симулировать обновление».

## Назначение
Вымышленные записи реестра для сценария жюри (АРХ §2). `ingest --demo` собирает из `base.tsv` снапшот версии 1 (`demo_stage = 0`), из `next.tsv` — версии 2 (`demo_stage = 1`), считает diff и регистрирует обе в `snapshot_version`. В образе каталог лежит в `/opt/sertkontrol/demo`.

## ДАННЫЕ ТЕСТОВЫЕ
Все записи вымышлены (КЕЙС §2 п.10): наименования «ТЕСТОВЫЙ …», ИНН — вымышленные с верной контрольной цифрой (АРХ §7.7), `registry_id = 0`, поэтому ссылка на реестр ведёт на страницу поиска, а не на чужую реальную запись. Номер `RU Д-CR.РА08.В.89369/26` взят из АРХ (выписка спайка), остальные его поля — тестовые. Интерфейс помечает такие вердикты «тестовые данные».

## Формат `*.tsv`
- UTF-8, разделитель — табуляция, строки `#…` — комментарии.
- Обязательная строка `#source_date=YYYY-MM-DD` — дата актуальности данных («Данные реестра на …»).
- Первая некомментированная строка — имена колонок ровно в таком порядке: `number status issue_date expiry_date status_date suspended_until applicant_name applicant_inn manufacturer_name product tnved country lab_accreditation registry_id`.
- `number` — как в документе (канонизирует `ingest`); `status` — формулировка реестра («Действует», «Приостановлен», «Прекращён», «Аннулирован», «Архивный», «Возобновлён», «Продлён»); даты — `YYYY-MM-DD` или пусто; `registry_id` — целое, `0` — неизвестен.
