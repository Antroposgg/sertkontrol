# libs/verify — поиск и правила вердикта (C4, владелец R2)

**Статус:** этап 1 — точный поиск, правила статуса и срока, ближайшие номера. Нечёткий поиск — этап 3.

## Назначение и границы
- Делает: `verify::check(snapshot, query)` → `Verdict` с метками «факт / расчёт / рекомендация», «нет в данных на <дату>» и до 3 ближайших номеров; общие представления (даты, названия статусов, ссылки на реестр, номер для людей).
- НЕ делает: IO, БД, распознавание, оформление сообщений бота и экранов (это `apps/certd/bot`, `web/`).

## Ключевые файлы
| Файл | Что внутри |
|---|---|
| `src/verify.cpp` | `check`: точный поиск (`equal_range` + сравнение строки), `apply_rules`, `nearest` |
| `include/sertkontrol/verify/text.hpp`, `src/text.cpp` | `format_date`, `status_name`, `kind_name`, `registry_url`, `display_number`, константы `kExpiringSoonDays = 30`, `kMaxSuggestions = 3` |
| [`docs/rules.md`](../../docs/rules.md) | Каталог правил — часть контракта C4 |

## Публичный интерфейс
`sk::verify::check`, `Verdict`, `Finding`, `Card`, `Suggestion` — в контрактном заголовке; представления — `sertkontrol/verify/text.hpp`. Цель CMake — `sk::verify`.

## Куда добавлять правило вердикта
1. Строка в [`docs/rules.md`](../../docs/rules.md) (id, основание, условие, текст).
2. Реализация в `apply_rules` (`src/verify.cpp`).
3. Строка в `RulesTest.Table` (`tests/verify/rules_test.cpp`). Тест `EveryRuleIsDocumentedInCatalog` не даст забыть п.1.

## Зависимости
- Зависит от: `sk::contracts`, `sk::canon`, `sk::snapshot`.
- От него зависят: `apps/certd` (DomainService, бот, REST).

## Инварианты
- Чистая функция: без IO; «сегодня» — `Query::today`.
- Точный поиск проверяет весь `equal_range` и сравнивает полную строку (АРХ §7.2).
- `Verdict` хранит только `std::string` — переживает `co_await` и замену снапшота (АРХ §7.4).
- Для записей без `registry_id` ссылка ведёт на страницу поиска реестра, а не на чужую запись.

## Потоки
Поток A, шаг 4 (АРХ §4).

## Тесты
`tests/verify/` → `verify_test`: табличный тест 13 случаев на настоящем снапшоте, основания меток, поля карточки, тексты с датами, ближайшие номера, сверка с каталогом, представления.

## Ограничения и отложенное
Ближайшие номера — только та же серия и год, обычное расстояние Левенштейна по байтам; взвешенное расстояние, варианты серии, пороги и `needs_confirmation` — этап 3.
