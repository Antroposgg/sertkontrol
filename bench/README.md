# bench — Google Benchmark против целей АРХ §2

**Статус:** этап 3.

| Бенчмарк | Что меряет | Цель (АРХ §2) |
|---|---|---|
| `bm_exact_lookup` | `verify::check` существующего номера: канонизация, XXH3, `equal_range`, правила вердикта | p99 ≤ 1 мс |
| `bm_fuzzy_lookup` | номер с искажённой цифрой серии: варианты серии в `serial_index` + взвешенный Левенштейн | p99 ≤ 5 мс |
| `bm_not_found_lookup` | номера нет: полный перебор вариантов серии впустую | p99 ≤ 5 мс |
| `bm_canonicalize` | канонизация строки из выписки | — |
| `bm_diff` | diff двух снапшотов, 1% записей изменён | ingest ≤ 15 мин целиком |

Снапшот синтетический: `SK_BENCH_N` записей (по умолчанию 1 000 000), серии — 5 цифр, годы 20–26, то есть
в среднем 1–2 номера на пару (серия, год), как в реестре. Перцентили — счётчики `p50_us`, `p99_us`, `max_us`
(Google Benchmark сам даёт только среднее).

## Запуск

```bash
scripts/ci/bench.sh
```

Скрипт собирает пресет `bench` (GCC 13, Release), пишет `build/bench/report.json` и падает, если p99 выше цели.
Результаты последнего прогона — в `docs/plan.md` (ворота этапа 3).

## Ограничения
- Реальный N неизвестен до подтверждения набора ФСА (АРХ §6: 5·10⁶–2·10⁷). Поиск — O(log N) по ключам и O(1)
  обращений к индексу серий, поэтому рост N сказывается слабо; при N = 2·10⁷ стоит перепроверить на холодном кэше.
- Замеры на прогретом `mmap`: холодный старт (первое обращение к страницам) не измеряется.
