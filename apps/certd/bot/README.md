# apps/certd/bot — диалоги бота MAX (владелец R4)

**Статус:** этап 3 — «Это номер …?» при нечётком совпадении (`confirm_question`, `[Да] [Нет]`), кнопка «Подробнее»
открывает «Документ» в мини-приложении (`document_start_param`).
Этап 2 — уведомления о смене статуса (`render_change_notice`) и диалог «Указать поставщика».
Этап 1 — согласие, справка, проверка номера и PDF, карточка, сводка, «На контроль», «Поставить все», «Снять».

## Назначение и границы
- Делает: событие webhook → вызовы `DomainService` (C6) → сообщения в outbox (C9) и ответы на кнопки.
- НЕ делает: доменную логику и SQL — только через C6, поэтому бот и мини-приложение показывают одинаковый вердикт (АРХ §5).

## Сценарии (АРХ §8)
| Событие | Ответ |
|---|---|
| `bot_started` | Без согласия — приветствие и `[Согласен] [Как это работает]`; с согласием — справка |
| `/start`, `/help` текстом (в т. ч. `/start@бот`) | Справка; текст после команды проверяется как обычный; без согласия — приветствие. `bot_started` MAX шлёт только при первом запуске |
| Любое сообщение без согласия | Приветствие (данные не обрабатываются, АРХ §10) |
| Текст с 1–3 номерами | Карточка на каждый: заголовок со статусом, «Тестовые данные», блоки Факт / Расчёт / Рекомендация, «Данные реестра на …»; `[На контроль]`, `[Открыть в реестре]`, `[Подробнее]` |
| Номер не найден, но есть уверенный нечёткий кандидат (АРХ §7.2) | «Это номер <кандидат>?» `[Да] [Нет]`; «Да» (`y:<check_id>`) — `DomainService::confirm` и обычная карточка, «Нет» (`n:<check_id>`) — «Пришлите номер ещё раз…» |
| Текст с 4–20 номерами | Сводка «N действуют, …» и `[Поставить все на контроль] [Открыть список]` |
| PDF-файл | «⏳ Проверяю документ…» (приоритет выше), затем карточки |
| Фото, не PDF, > 20 МБ, нет номера | Понятное сообщение об ошибке |
| `[Указать поставщика]` (`s:<check_id>`) | «Пришлите ИНН поставщика — 10 или 12 цифр…»; диалог `awaiting_inn` в `dialog_state` (30 мин) |
| ИНН в ответ | Документ ставится на контроль с поставщиком (или поставщик обновляется) → «… на контроле, поставщик — ИНН …» |
| Неверный ИНН (контрольные цифры) | «ИНН не прошёл проверку…», диалог продолжается |
| «отмена» / `/cancel` | «Хорошо, поставщика не указываю.», диалог закрыт |
| Не цифры (например, номер документа) или вложение | Диалог закрыт, сообщение обрабатывается как обычно |
| Смена статуса (задача `notify_changes`) | Одно сообщение на пользователя и версию: «Декларация … — <b>приостановлен</b> до … (было: действует). SKU … Данные реестра на …»; `[Открыть портфель]`; длинный список делится на сообщения ≤ 4000 символов |

Callback payload `<действие>:<id>`: `w:<check_id>` на контроль, `W:<batch_id>` все из пачки, `d:<portfolio_item_id>` снять,
`s:<check_id>` указать поставщика, `y:`/`n:<check_id>` ответ на «Это номер …?», `c:1` согласие, `h:1` справка.
`[Подробнее]` — `open_app` с `payload = doc-<hex UTF-8 номера>`: только `[A-Za-z0-9_-]` и ≤ 512 символов (ограничения
`start_param` MAX), мини-приложение открывает по нему «Документ». id — строки БД, владелец проверяется доменом.

## Инварианты
- Текст — HTML MAX (`<b>`), все данные экранируются `html_escape`; сообщения ≤ 4000 символов, кнопки `link`/`open_app` ≤ 3 в ряду — проверяет `maxapi::validate`.
- Кнопки `open_app` — только если известен username бота (`GET /me`, запасной — `MAX_BOT_USERNAME`): `web_app`
  обязателен, и с отображаемым именем вместо username MAX отвергает сообщение целиком.

## Зависимости
`../domain.hpp` (C6), `../ports.hpp` (outbox C9, `DialogStore`), `../notify.hpp` (`ChangeNotice` — только тип входа
рендера; `NotifyService` вызывает рендер через `NoticeRenderer`, собранный в `main.cpp`), `libs/maxapi` (события,
сообщения, ответы на кнопки).

## Тесты
`tests/certd/bot_test.cpp` на `FakeDomainService`, `MemoryOutbox`, `MemoryDialogStore` и `RecordingBotApi`: все
сценарии выше, согласие, ошибки вложений, дедупликация webhook, диалог ИНН, рендер уведомлений (одно сообщение на
пользователя, деление > 4000 символов). Сквозной сценарий на PostgreSQL — `tests/certd/jury_scenario_test.cpp`.

## Ограничения
- «Затронуты SKU …» перечисляет SKU только тех позиций, где он указан (ввод SKU — мини-приложение и импорт CSV, этап 4).
