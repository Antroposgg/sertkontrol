# apps/certd/bot — диалоги бота MAX (владелец R4)

**Статус:** этап 1 — согласие, справка, проверка номера и PDF, карточка, сводка, «На контроль», «Поставить все», «Снять».
Уведомления о смене статуса — этап 2.

## Назначение и границы
- Делает: событие webhook → вызовы `DomainService` (C6) → сообщения в outbox (C9) и ответы на кнопки.
- НЕ делает: доменную логику и SQL — только через C6, поэтому бот и мини-приложение показывают одинаковый вердикт (АРХ §5).

## Ключевые файлы
| Файл | Что внутри |
|---|---|
| `bot.hpp/.cpp` | `Bot::handle`: `bot_started`, `message_created` (текст, PDF, фото), `message_callback` |
| `card.hpp/.cpp` | Чистые функции: `welcome`, `help`, `verdict_card`, `summary`, `watched`, `error_message`, `progress`, `parse_callback` |

## Сценарии (АРХ §8)
| Событие | Ответ |
|---|---|
| `bot_started` | Без согласия — приветствие и `[Согласен] [Как это работает]`; с согласием — справка |
| Любое сообщение без согласия | Приветствие (данные не обрабатываются, АРХ §10) |
| Текст с 1–3 номерами | Карточка на каждый: заголовок со статусом, «Тестовые данные», блоки Факт / Расчёт / Рекомендация, «Данные реестра на …»; `[На контроль]`, `[Открыть в реестре]`, `[Подробнее]` |
| Текст с 4–20 номерами | Сводка «N действуют, …» и `[Поставить все на контроль] [Открыть список]` |
| PDF-файл | «⏳ Проверяю документ…» (приоритет выше), затем карточки |
| Фото, не PDF, > 20 МБ, нет номера | Понятное сообщение об ошибке |

Callback payload `<действие>:<id>`: `w:<check_id>` на контроль, `W:<batch_id>` все из пачки, `d:<portfolio_item_id>` снять,
`c:1` согласие, `h:1` справка. id — строки БД, владелец проверяется доменом.

## Инварианты
- Текст — HTML MAX (`<b>`), все данные экранируются `html_escape`; сообщения ≤ 4000 символов, кнопки `link`/`open_app` ≤ 3 в ряду — проверяет `maxapi::validate`.
- Кнопки `open_app` — только если задан `MAX_BOT_USERNAME` (`web_app` обязателен в MAX API).

## Зависимости
`../domain.hpp` (C6), `../ports.hpp` (outbox, C9), `libs/maxapi` (события, сообщения, ответы на кнопки).
