# Каталог правил вердикта (контракт C4)

Каждая строка карточки вердикта — `verify::Finding` с идентификатором правила и основанием (КЕЙС §7 п.3):

- **факт** — взято из данных реестра как есть;
- **расчёт** — вычислено продуктом из фактов;
- **рекомендация** — совет продукта, а не юридическое заключение (юридические заключения — Won't, АРХ §2).

Реализация — [`libs/verify/src/verify.cpp`](../libs/verify/src/verify.cpp). Тест `RulesTest.EveryRuleIsDocumentedInCatalog`
падает, если код выдаёт правило, которого нет в этом каталоге; табличный тест `RulesTest.Table` фиксирует набор
правил для каждого случая. «Сегодня» — `Query::today` (в `certd` — текущая дата по Москве), «дата данных» — дата
актуальности снапшота.

## Уровень вердикта

| Уровень | Условие |
|---|---|
| `ok` | Статус «действует», срок не истёк и до окончания больше 30 дней (или дата окончания не указана) |
| `warning` | Статус «действует» и до окончания 0–30 дней; либо статус не распознан и срок не истёк |
| `problem` | Статус не «действует» (кроме нераспознанного) или срок истёк |
| `not_found` | Номер не распознан или отсутствует в снапшоте |
| `needs_confirmation` | Точного совпадения нет, но нечёткий поиск уверен: лучший кандидат на расстоянии ≤ 2 и отрыв от второго ≥ 0,5 |

## Статус

| Правило | Основание | Когда | Текст |
|---|---|---|---|
| `status.active` | факт | статус «действует» | Статус в реестре: действует |
| `status.suspended` | факт | «приостановлен» | Статус в реестре: приостановлен [до ДД.ММ.ГГГГ] [(с ДД.ММ.ГГГГ)] |
| `status.terminated` | факт | «прекращён» | Статус в реестре: прекращён [(с ДД.ММ.ГГГГ)] |
| `status.annulled` | факт | «аннулирован» | Статус в реестре: аннулирован [(с ДД.ММ.ГГГГ)] |
| `status.archived` | факт | «архивный» | Статус в реестре: архивный [(с ДД.ММ.ГГГГ)] |
| `status.unknown` | факт | статус источника не сопоставлен | Статус в реестре: не распознан |

Дата «с …» — `status_date`, показывается для любого статуса, кроме «действует».

## Срок

| Правило | Основание | Когда | Текст |
|---|---|---|---|
| `term.period` | факт | есть дата окончания | Срок действия: с ДД.ММ.ГГГГ по ДД.ММ.ГГГГ (или «по …», если нет даты начала) |
| `term.unknown` | факт | нет даты окончания | Дата окончания действия в реестре не указана |
| `term.expired` | расчёт | окончание < сегодня | Срок действия истёк ДД.ММ.ГГГГ — N дн. назад |
| `term.expiring` | расчёт | 0 ≤ дней до окончания ≤ 30 | Срок действия истекает через N дн. |
| `term.remaining` | расчёт | дней до окончания > 30 | До окончания срока действия N дн. |

## Не найдено

| Правило | Основание | Когда | Текст |
|---|---|---|---|
| `number.unparsed` | расчёт | в запросе нет номера вида `RU D-…` / `RU C-…` | Не удалось распознать номер: ожидается вид «ЕАЭС N RU Д-RU.РА01.В.12345/23» |
| `not_found` | факт | номер распознан, но отсутствует в снапшоте | Номера нет в данных реестра на ДД.ММ.ГГГГ |
| `not_found.recent` | расчёт | `not_found` без уверенного кандидата и год в номере (`/ГГ`) = год даты данных (V5) | Номер ГГГГ года: документ мог быть зарегистрирован после ДД.ММ.ГГГГ — проверьте его по ссылке из QR-кода выписки |
| `fuzzy.match` | расчёт | уровень `needs_confirmation` | Похоже на номер RU Д-… — возможна ошибка распознавания или опечатка |

## Нечёткий поиск (АРХ §7.2)

Реализация — [`libs/verify/src/fuzzy.cpp`](../libs/verify/src/fuzzy.cpp).

- **Расстояние** — взвешенный Левенштейн по кодовым точкам: вставка, удаление, замена — 1; замена из таблицы
  путаницы OCR (O↔0, B↔8, S↔5, I↔1, Z↔2) — 0,3.
- **Кандидаты** — записи `serial_index` с серией и годом запроса (буквы-двойники в серии и годе заменены цифрами)
  и с серией, отличающейся одной цифрой (длина × 9 обращений к индексу). Если в серии одна буква без двойника,
  она считается искажённой цифрой — 10 вариантов.
- **Порог** — лучший кандидат ≤ 2 и отрыв от второго ≥ 0,5 → `needs_confirmation` и вопрос «Это номер …?»;
  иначе `not_found` и до 3 ближайших номеров в `Verdict::suggestions`. Точный номер никогда не подменяется молча.
- **Полнота** — property-тест `FuzzyProperty.MatchesBruteForceOn10kRecords`: если лучший по полному перебору номер
  отличается от запроса не больше чем одной цифрой серии и совпадает по году, нечёткий поиск находит кандидата с тем
  же расстоянием. Не ищутся номера с искажённым годом или со вставкой/удалением цифры в серии.

## Рекомендации

| Правило | Основание | Когда | Текст |
|---|---|---|---|
| `advice.watch` | рекомендация | уровень `ok` или `warning` | Поставьте документ на контроль — пришлём уведомление, если статус изменится |
| `advice.renew` | рекомендация | `term.expiring` | Запросите у поставщика новый документ заранее — срок истекает через N дн. |
| `advice.check_status` | рекомендация | статус не распознан | Статус в данных не распознан: проверьте запись по ссылке на реестр |
| `advice.replace` | рекомендация | уровень `problem` | Документ не действует на дату данных реестра: запросите у поставщика действующий документ |
| `advice.confirm_number` | рекомендация | `needs_confirmation` | Подтвердите номер — покажем его карточку |
| `advice.check_number` | рекомендация | `not_found` | Сверьте номер с документом; если он верный — запросите у поставщика подтверждение регистрации (или «в реестре есть похожие номера») |

## Поля карточки (факт)

Вид документа, статус, даты регистрации, окончания и смены статуса, заявитель и его ИНН, изготовитель, продукция
(до 128 байт), ТН ВЭД, ссылка на реестр, «Данные реестра на <дата>» и пометка «тестовые данные», если снапшот демо.

Ссылка на реестр: `https://pub.fsa.gov.ru/rds/declaration/view/<registry_id>/common` для деклараций,
`https://pub.fsa.gov.ru/rss/certificate/view/<registry_id>/common` для сертификатов; если `registry_id` неизвестен
— страница поиска соответствующего реестра. В демо-снапшоте ссылка всегда ведёт на страницу поиска, даже если у записи
есть `registry_id` (он нужен, чтобы QR тестовой выписки находил демо-запись): поля демо вымышлены, и ссылка не должна
вести на чужую реальную запись.

**Поиск по ссылке (F10).** Текст запроса со ссылкой `pub.fsa.gov.ru/rds/declaration/view/<id>` или
`pub.fsa.gov.ru/rss/certificate/view/<id>` (QR выписки, вставленная ссылка) проверяется по записи с этим
`registry_id` и тем же видом документа (`verify::parse_registry_url`, `Snapshot::by_registry_id`). Ссылка идёт
раньше номеров из текста; записи нет — ошибка `not_found_in_snapshot` «записи реестра по этой ссылке нет в данных на
ДД.ММ.ГГГГ».

## Как добавить правило

1. Строка в этот каталог: идентификатор, основание, условие, текст.
2. Реализация в `apply_rules` (`libs/verify/src/verify.cpp`).
3. Строка в `RulesTest.Table` (`tests/verify/rules_test.cpp`).
4. Если правило меняет уровень — обновить таблицу «Уровень вердикта».
