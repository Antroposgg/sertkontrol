# ADR-0013: Мини-приложение без MAX при локальном запуске — dev-пользователь

- Статус: принят
- Дата: 2026-09-27
- Связано: ADR-0006, КЕЙС §4 п.3 («пошаговый сценарий проверки»), АРХ §8, §10

## Контекст
REST `/api/v1` принимает только подписанную initData (ADR-0006). initData выдаёт клиент MAX и подписывает токеном
бота. Жюри и разработчики поднимают стек `docker compose up` без токена и открывают мини-приложение в браузере —
без initData каждый запрос получал бы 401, и экраны нельзя проверить.

## Решение
Переменная `CERTD_DEV_USER_ID` (в `compose.yaml` по умолчанию `1000001`): запрос **без** заголовка `X-Max-Init-Data`
выполняется от этого пользователя — но только если `MAX_BOT_TOKEN` пуст. При заданном токене переменная
игнорируется с предупреждением в логе, и вход возможен только по initData. certd пишет в лог предупреждение, когда
режим включён.

## Альтернативы
- Требовать токен для локального запуска — ломает «одну команду» КЕЙСА, токен нельзя класть в репозиторий.
- Подписывать тестовую initData на клиенте фиктивным токеном — тот же уровень защиты, но сложнее и незаметнее.
- Ошибка конфигурации при одновременном задании токена и dev-пользователя — ломает общий `compose.yaml` для
  локального запуска и VPS.

## Последствия
Без токена certd — однопользовательский локальный стенд: любой, кто достучится до порта, работает от dev-пользователя.
Поэтому на VPS токен обязателен (без него нет и бота), а README предупреждает не публиковать порт без токена.
Проверено тестами `Config.DevUserOnlyWithoutBotToken` и `RestApiDevAuth.DevUserOnlyWithoutToken`.

## Когда пересмотреть
Появятся внешние клиенты API или многопользовательский стенд без MAX.
