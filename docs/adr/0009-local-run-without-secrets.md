# ADR-0009: Локальный запуск без секретов — PostgreSQL `trust` во внутренней сети

- Статус: принят
- Дата: 2026-09-26
- Связано: КЕЙС §2 п.8, §4 п.3 и п.5; АРХ §10; docs/plan.md, противоречие 2

## Контекст
КЕЙС требует одной команды запуска и запрещает рабочие пароли в репозитории; `.env.example` — с пустыми значениями. Образ `postgres:16` без пароля не стартует.

## Решение
В `compose.yaml` значение по умолчанию `POSTGRES_HOST_AUTH_METHOD=trust`, пароль пуст. Порт 5432 наружу не публикуется: БД доступна только контейнерам проекта. На VPS в `.env` задаются `POSTGRES_PASSWORD` и `POSTGRES_HOST_AUTH_METHOD=scram-sha-256`; `certd` передаёт пароль в строку подключения, если он задан.

## Альтернативы
Пароль по умолчанию в `compose.yaml` — публично известный «секрет» того же уровня защиты, ловится gitleaks. Обязательный `.env` — ломает «одну команду».

## Последствия
`postgres` пишет предупреждение про `trust` в лог — ожидаемо. README (раздел «Безопасность») требует пароль для любого развёртывания вне локальной машины.

## Когда пересмотреть
Если compose начнут запускать на общих хостах — сделать пароль обязательным.
