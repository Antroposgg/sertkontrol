# ADR-0016: Контрактные тесты без проверки `unsupported_method` schemathesis

- Статус: принят
- Дата: 2026-09-29
- Связано: АРХ §10 («Интеграция», контрактные тесты), ADR-0003 (Drogon 1.8.7 из apt), CLAUDE.md (отключение проверок — только через ADR)

## Контекст
schemathesis (`--checks all`) проверяет, что на неподдерживаемый метод сервис отвечает 405 с заголовком `Allow`
(RFC 9110 §15.5.6). `certd` добавляет `Allow` ко всем 405 советом `registerPreSendingAdvice`
(`apps/certd/rest_api.cpp`, `install_allow_header`). Но `TRACE` Drogon 1.8.7 не знает: разборщик HTTP отвечает 405
до маршрутизации и советов, перехватить этот ответ из приложения нельзя. schemathesis проверяет в том числе `TRACE`.

## Решение
`scripts/ci/contract-test.sh` запускает schemathesis с `--exclude-checks unsupported_method`, а вместо неё сам
проверяет каждый путь `openapi.yaml` методами `PUT` и `PATCH`: ответ обязан быть 405 с `Allow`. Остальные проверки
schemathesis (коды, схемы ответов, заголовки, авторизация, 5xx, stateful-цепочки) остаются включёнными.

## Альтернативы
- Drogon 1.9.x из исходников — нарушает ADR-0003 (сборка в лимит, только apt).
- Отклонять `TRACE` в Caddy — контрактный тест идёт напрямую в `certd`, а локальный стек жюри работает без Caddy.

## Последствия
`TRACE` получает 405 без `Allow` — несоответствие RFC без влияния на безопасность (тело пустое, запрос не обрабатывается).
Записано в «известных ограничениях» README.

## Когда пересмотреть
Переход на Drogon, где разборщик знает `TRACE`, или появление в schemathesis выбора методов для этой проверки.
