# ADR-0012: Корневой сертификат Минцифры в образе certd

- Статус: принят
- Дата: 2026-09-27
- Связано: АРХ §9 (OpenSSL), §10 (Dockerfile); docs/plan.md §5.1

## Контекст
Документация MAX требует обращаться к `https://platform-api2.max.ru` и «добавить сертификат Минцифры в список доверенных».
Проверено: сертификат `*.max.ru` выпущен «Russian Trusted Sub CA», корня «Russian Trusted Root CA» в `ca-certificates`
Ubuntu 24.04 нет — `openssl s_client` и `curl` дают ошибку проверки 20. Без корня бот не может отправлять сообщения.

## Решение
Публичный корневой сертификат лежит в `docker/certs/russian_trusted_root_ca.crt` (источник — gu-st.ru). Dockerfile
копирует его в `/usr/local/share/ca-certificates/`, сверяет SHA-256 отпечаток (`D2:6D:…:CF:31`) и выполняет
`update-ca-certificates`. `HttpBotApi` использует системное хранилище OpenSSL, проверка сертификата остаётся включённой.

## Альтернативы
- Отключить проверку TLS для MAX — недопустимо: токен бота уходит в заголовке.
- Скачивать сертификат при `docker build` — сборка зависит от доступности gu-st.ru и не воспроизводима.
- Доверять только этому корню только для клиента MAX (отдельный CA-файл) — Drogon 1.8.7 не даёт задать CA-файл
  для `HttpClient`.

## Последствия
Корень Минцифры доверен всему процессу certd (и ingest, который в сеть не ходит). Срок действия — до 27.02.2032.
Для локальной разработки на хосте нужно добавить тот же файл в системное хранилище (README).

## Когда пересмотреть
Корень появится в `ca-certificates` Ubuntu или MAX сменит удостоверяющий центр.
