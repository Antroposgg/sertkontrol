# ADR-0015: Исходящие HTTPS-запросы к MAX — libcurl, а не `drogon::HttpClient`

- Статус: принят
- Дата: 2026-09-29
- Связано: АРХ §9 (Drogon — HTTP), ADR-0003, ADR-0012

## Контекст
На VPS бот принимал события (TLS входящих запросов снимает Caddy), но ни одно сообщение не ушло: MAX отвечал
`400 The plain HTTP request was sent to HTTPS port`. Воспроизведено локально: `trantor::utils::tlsBackend()` пакета
Ubuntu 24.04 возвращает `None` — trantor собран без TLS, и `drogon::HttpClient` для `https://` молча шлёт открытый
HTTP на порт 443, вместе с токеном бота в заголовке. Тесты этого не ловили: они проверяли клиента по `http://`.

## Решение
`maxapi::HttpBotApi` выполняет исходящие запросы через libcurl (`libcurl4-openssl-dev` 8.5.0 из apt) в собственном
пуле потоков; корутины ждут результат через `co_await`. Протоколы ограничены `https` (http — только если так задан
`base_url` в тестах), проверка сертификата и имени хоста включена, корень Минцифры — в системном хранилище
(ADR-0012). `certd` не стартует с включённым ботом, если libcurl собран без TLS. Входящий HTTP (сервер) остаётся на Drogon.

## Альтернативы
- Собрать trantor/Drogon с TLS из исходников — нарушает правило «C++-зависимости только из apt» и лимит сборки.
- Исходящий прокси через Caddy (certd → http → Caddy → https MAX) — ещё один компонент на пути токена, работает только в профиле `prod`.

## Последствия
Две HTTP-библиотеки: Drogon — сервер, libcurl — клиент. Тест `maxapi_tls_test` поднимает `openssl s_server` и проверяет
настоящее TLS-соединение, отказ на недоверенном сертификате и лимит размера.

## Когда пересмотреть
Ubuntu начнёт собирать trantor с TLS или проект перейдёт на Drogon из исходников.
