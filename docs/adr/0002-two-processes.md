# ADR-0002: Два процесса: `certd` и `ingest`

- Статус: принят
- Дата: 2026-09-26
- Связано: АРХ §3, §4 «Поток B»

## Контекст
Сборка снапшота требует пиковой памяти и разбирает внешние данные непредсказуемого качества; бот должен отвечать непрерывно.

## Решение
Отдельный процесс `ingest` (тот же образ, другая точка входа). Связь с `certd` — только файл в общем томе и `NOTIFY snapshot_ready` в PostgreSQL.

## Альтернативы
Ingest потоком внутри `certd`: падение парсера или пик памяти роняют бота.

## Последствия
Ingest можно запускать вручную (`docker compose run --rm ingest --once`) и в CI. Нужен протокол готовности: `snapshot_version.status = 'ready'` + `NOTIFY`.
